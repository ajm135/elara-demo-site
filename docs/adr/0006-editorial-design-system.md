# 0006: Token-driven editorial design system and local type

- Status: accepted
- Date: 2026-10-18

## Context

Milestone 3 redesigns the five existing pages into a light, contemporary 2026 science-editorial experience for general readers. The innovation review and the operator's direction require: a warm neutral, ink-on-paper feel with a restrained accent; expressive but calm typography; generous spacing and composed hero layouts; readable evidence panels; a long-form measure of about 60–75 characters; WCAG 2.2 AA with visible keyboard focus and comfortable navigation targets; header-only story navigation that orients readers to their position in the five-story sequence; and typography that never requires a remote stylesheet or JavaScript for reading.

The previous stylesheet hard-coded a few colour values (`#fffdfb`, `#1a1a1a`, `#0b3d91`) and the tests matched those exact strings, which is brittle: it cannot tell whether a palette is warm or whether a new pair of colours still meets AA, and it pins the design to one navy accent.

Two practical constraints shape the typography decision: the fonts must be committed local files (the site is loopback-only and rendering must not require remote assets), and no font may be fetched from the network. The only verifiable, freely redistributable font sources on this computer are the Inter "18pt" build (SIL Open Font License 1.1, verified from the font files' embedded `name` tables) and the Geist Regular build shipped inside the `next` package (also OFL 1.1). No variable-font master of either family is available locally.

## Decision

- `src/app/globals.css` is a token-driven design system. All colours, the measure, and the rules come from custom properties in `:root`: warm neutral surfaces (`--surface-page` `#f6f1e7`, `--surface-raised` `#fdfbf6`, a distinct `--surface-evidence` `#e9efe9` for evidence panels), dark warm ink (`--ink-heading`, `--ink-body`, `--ink-muted`), a restrained teal accent with a depth step (`--accent-teal` `#0e6b63`, `--accent-teal-deep`), muted warm rules (`--rule-warm`, and `--rule-strong` for boundaries that carry meaning), and the long-form measure (`--measure: 40rem`). The page surface is not pure white, and the navy link colour `#0b3d91` is replaced by the teal accent.
- Contrast is verified, not asserted: `tests/design-tokens.test.ts` parses the tokens from `globals.css` and computes WCAG 2.2 ratios — 4.5:1 for every normal-text pair (body, headings, muted meta, links, visited links, and citations on all three surfaces) and 3:1 for meaningful UI boundaries. `tests/accessibility-essentials.test.ts` keeps the AA essentials of the base rules (body pair, underlined links, focus outline) but computes them from the same tokens; the old exact colour-string expectations were replaced by these stronger, semantic checks, with no accessibility requirement skipped or weakened.
- The interaction rules are part of the system: links are underlined everywhere (colour is never the only cue); `:focus-visible` is a solid 3px accent outline with an offset; the skip link is off-screen until focused; navigation targets are at least 44×44 CSS px; body text is 1rem at line-height 1.6; the content column is capped at the measure token; there is no `100vw`, no min-width above 320 px, no animation, no `text-transform` on navigation labels, and no hover-only information.
- Reusable layout rules ship with the tokens: a header progress cluster (`.progress-cluster` with story position, next-story cue, and ending state), a composed hero (`.hero` with a framed `.hero-media` illustration), the evidence panel (`.claim-evidence` on the distinct evidence surface with a strong accent left edge), and the content stack (`main` with open block spacing and a ruled-off disclaimer). The header remains the only navigation: no hamburger, no second nav, nothing that needs JavaScript.
- Local type: `src/app/fonts/` commits `inter-regular.ttf` (body, weight 400) and `inter-bold.ttf` (headings, weight 700) — the Inter "18pt" build by Rasmus Andersson and the Inter Project authors, SIL OFL 1.1 as recorded in the font files' own `name` tables — with a short provenance and license note beside them (`src/app/fonts/LICENSE.md`). The files were copied from a local installation on this computer; nothing was fetched.
- The fonts are wired in a server-only module, `src/lib/fonts.ts`, with `next/font/local`. The root layout applies the two generated classes to `<html>`, which exposes the `--font-body` and `--font-heading` CSS custom properties; `globals.css` consumes those variables with system-font fallbacks. There is no remote stylesheet, no `@import`, no `use client`, and no JavaScript required for reading; the fonts are served by this computer's own server.
- The fonts are static single-weight builds rather than one variable font: no variable-font master was available on this computer and fetching fonts is forbidden for this milestone, so the body/heading pairing uses two fixed weights (400/700) of the same family. This is recorded as a deliberate deviation from a variable axis, not a gap to hide.
- Reading progress lives in the content model, not in components: `src/lib/site-content.ts` gains the pure helpers `storyIndex(pageId)` (1-based position in `sitePages` order), `storyPositionLabel(pageId)` (exactly "Story N of 5"), and `nextStory(pageId)` (the following page, or `null` on the final story), plus an optional `reviewedOn` ISO date on `SitePage`. Every shipped page carries `reviewedOn: "2026-10-18"`, the date every source in the reference catalogue was actually inspected for the claim evidence register (ADR 0005, `docs/runbooks/content-evidence.md`); no different date is invented. No shipped claim sentences, stages, last-reviewed dates, reference catalogue entries, disclaimers, routes, or headings change.
- Shipped copy, routes, the five-story reading order, the no-account/no-database architecture, and loopback-only hosting (ADR 0001–0004) are all preserved by this decision.

## Notes

- This ADR does not claim browser-level verification: the token contrast and structure checks run in Node against the stylesheet text. The project's browser and accessibility evidence — Elara's milestone 3 browser checks recorded as passed on 2026-10-20 against the final design, the executed Node-only safeguard, and the manual checks still to do — is recorded in `docs/runbooks/accessibility-validation.md`; those records are not complete WCAG 2.2 AA conformance or complete cross-browser verification, and the manual checks still to do there (screen-reader navigation, 200% and 400% zoom and reflow, JavaScript-off reading in a real browser, native Safari on macOS and iOS, an in-browser accessibility audit, the dark theme in a real browser, and reduced-motion behaviour) remain to be run.
- The reusable Elara browser-check definitions for the reading experience live in `tests/e2e/reading-experience.json`. `npm run verify:reading` (`scripts/verify-reading.mjs`) is a Node-only loopback HTTP safeguard: it starts and stops its own loopback production server and checks the five server-rendered HTTP responses for the essential story content, local illustrations, citations, disclaimers, the ordinary navigation links, and the correct current-page state, using the definition data in that file. It never executes page JavaScript and never launches a browser, and its results are safeguards, not proof of complete no-JavaScript browser behaviour or WCAG 2.2 AA conformance. The recorded results of Elara's milestone 3 browser checks (passed, 2026-10-20, against the final design recorded in `docs/adr/0007-immersive-2026-design.md`) are in `docs/runbooks/accessibility-validation.md`, and they are not complete WCAG or cross-browser verification. This ADR covers the tokens, type, and progress model only.
- Tests: `tests/design-tokens.test.ts` (token set, warm surfaces, AA contrast pairs, boundaries, underline, focus, measure, absence of the legacy navy, structural hygiene), `tests/story-progress.test.ts` (helpers and review dates), and the updated `tests/accessibility-essentials.test.ts` (token-computed AA essentials).
